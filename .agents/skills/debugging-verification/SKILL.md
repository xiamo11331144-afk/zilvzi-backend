# 调试与验证

## 调试纪律
1. 先收集可复现步骤、期望与实际结果、时间点、运行环境和错误原文；不凭猜测直接改代码。
2. 检查工作树与相关文件，沿调用链定位首个异常点：页面事件/请求 -> HTTP -> Controller -> Service -> 数据访问/外部依赖 -> 响应渲染。
3. 区分代码缺陷、数据问题、配置问题、服务未启动、网络/域名限制和第三方服务失败。
4. 优先做最小、局部、可解释的修复；避免为了绕过一个错误修改认证、关闭校验或吞掉异常。
5. 保留有用的异常上下文，日志中脱敏密码、token、密钥和个人数据；不要把临时调试日志留在生产路径。

## 验证层级
- 静态：引用、语法、字段/方法名、配置键、Mapper 绑定。
- 编译：后端 Maven 编译/测试；前端可用的脚本或微信开发者工具检查。
- 单元/集成：覆盖修复的分支、权限、异常、空数据、重复请求和事务边界。
- 运行：本地服务、MySQL/Redis、微信开发者工具或真实接口；记录依赖是否可用。
- 回归：检查调用方、相邻模块和数据库兼容性。

## 报告格式
说明复现结果、根因证据、改动文件、验证命令及结果。明确哪些路径已验证、哪些因环境限制未验证。若无法复现，保留诊断假设和下一步最小采集信息，不声称已修复。
