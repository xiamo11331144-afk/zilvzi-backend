# 项目分析

## 目标
基于当前源码建立准确的项目认知，为后续功能实现提供文件级、数据流级依据。不将 README 描述当作未经验证的实现事实。

## 分析步骤
1. 从工作区 `AGENTS.md`、根 `README.md` 和对应模块配置确认技术栈与运行入口。
2. 先检查工作树状态；不清理或覆盖用户改动。
3. 用路径搜索定位路由/页面、调用端、控制器、服务、Mapper/XML、实体、配置和 SQL；只读相关文件及必要上下游，不扫生成目录 `backend/target/`。
4. 沿真实调用链追踪：小程序页面事件 -> 请求封装 -> HTTP 路径/方法/参数 -> Controller -> Service -> Mapper/XML -> 数据表；回程追踪响应封装和 UI 状态。
5. 记录鉴权、输入校验、分页、空值/错误处理、事务、缓存、权限及数据变更边界。跨模块功能补充列出所有受影响入口。
6. 用文件路径和行号或具体符号支撑结论；将已证实事实、合理推测、待验证问题分开。

## 输出格式
- 项目结构与模块职责
- 目标业务的端到端链路（附关键文件）
- API 与数据模型要点
- 风险、耦合点和最小修改范围
- 可执行的验证建议及当前环境限制

没有用户提出修改前，不自行改代码。避免无依据地声称接口、表结构或部署行为。
