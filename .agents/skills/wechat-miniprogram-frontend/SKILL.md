# 微信小程序前端开发

## 项目约束
- `miniprogram/` 是原生微信小程序，不引入 React/Vue/NPM 构建链，不把 Web DOM/CSS API 当作可用能力。
- 先读取目标页面的 `.js/.wxml/.wxss/.json`、相关公共工具和 `app.js`；确认页面注册、tabBar、组件和生命周期。
- 网络请求优先复用 `miniprogram/utils/request.js`，遵守当前 token 注入、401 处理、响应结构和错误提示约定。
- 配置读取 `miniprogram/config/env.js`；不把真实服务密钥、令牌或生产地址写入源码。

## 修改流程
1. 沿页面事件找到请求方法和后端接口；核对参数、响应 `data` 结构、空态、加载态、失败态和重复点击行为。
2. 页面状态以最小改动维护，避免在 `setData` 中写入过大对象或频繁更新；异步请求在页面卸载/切换时考虑竞态和重复回调。
3. 交互控件使用小程序支持的事件与组件；处理 `wx:if`、`wx:for` 的 key、授权流程、返回刷新、下拉刷新和分页边界。
4. WXSS 遵循项目已有设计语言与尺寸，确保长文本、不同屏幕和安全区不溢出；不要为了样式换框架。
5. 需要改接口时同时核对后端契约，不用前端临时兼容掩盖服务端错误。

## 验证
- 先做 JS/WXML/JSON/WXSS 的静态检查和引用路径检查。
- 能运行时使用微信开发者工具验证关键流程：首屏、登录态、成功、空数据、网络失败、401 和重复操作。
- 若无法运行开发者工具，明确列出未完成的真实设备/模拟器验证，不把静态检查描述为联调成功。
