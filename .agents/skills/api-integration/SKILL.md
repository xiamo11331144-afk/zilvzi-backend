# 前后端接口联调

## 契约核对
1. 以实际 Controller 映射、参数绑定和返回类型为服务端事实，以小程序请求封装和调用页面为客户端事实。
2. 记录 HTTP 方法、完整路径、认证要求、请求字段及类型、成功响应、业务失败响应、HTTP 错误、空数据和分页语义。
3. 检查 `Result` 包装是否被全局处理器或某个接口特殊处理，避免重复包装或错误解包。
4. 文件上传单独确认 multipart 字段、文件大小/类型、临时路径、鉴权 header 和返回 URL；不要按 JSON 请求处理。

## 实施原则
- 先兼容现有调用方；新增字段尽量可选，字段重命名提供过渡或同步修改所有调用点。
- 用户身份从后端认证上下文取得，不能使用前端传来的 userId 作为权限依据。
- 分页明确页码起点、页大小上限、总数/列表字段；避免前端和 PageHelper 对分页定义不一致。
- 处理加载中、成功、空结果、业务失败、401、超时和重复提交；成功状态以真实响应语义判断，不只看 HTTP 200。
- 需要数据库变更时，同步检查旧数据、索引、回滚/兼容策略和部署顺序。

## 联调清单
- 路径和方法一致
- JSON 字段名、大小写、数值/字符串类型一致
- token 注入和拦截器路径一致
- 错误码与提示可被客户端正确处理
- 日期时间、布尔值、空值和枚举约定一致
- CORS、上传限制、超时与代理环境已核对

## 验证
优先用 mock 或本地服务做一条成功链路和关键失败链路；再运行后端测试/编译并做前端静态检查。未启动 MySQL、Redis、微信开发者工具或第三方服务时，明确标记对应验证未完成。
